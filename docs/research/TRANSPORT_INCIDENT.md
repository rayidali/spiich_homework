## What happened

The continuous dispatcher had completed 2,938 requests successfully when its next external tool operation was delayed. The queued request was created at 03:57:24.879Z and received the helper's pre-tool start timestamp around 03:57:28.127Z. Its response/footer files appeared at 03:59:24.905Z with HTTP 200 and a curl duration of 1.508 seconds. This supports a delay around command launch or orchestration, rather than a provider taking two minutes to answer. The exact platform cause is not established; the estimated network-start time is an inference from file timing and curl duration, not a packet capture.

The original caller's 25-second deadline expired. Two following generation requests and the final database-fingerprint request were never claimed or dispatched. Three generation attempts retained unknown usage, opening the existing circuit breaker; the next route recorded its local circuit-open failure and the runner stopped. The dispatcher then stopped cleanly after 2,939 sent requests, all with HTTP 200/full footers/curl exit zero. Successful late transport does not turn the original timed-out trial into success.

## The bounded operational changes

The external [transport recovery tool](../../scripts/recover-study-transport.ts) lives outside the frozen inference tree. It binds the actual timeout episode/usage IDs, complete usage prefix, existing policies and quota journal, incident evidence, fixed probe request/key, source/protocol and reviewed dispatcher files. It checks the original policies and caps through their existing exported validation functions. Its narrow fixed-probe pricing is checked against the frozen budget implementation in synthetic tests.

Preparation requires no active runner, dispatcher or outstanding queue work. Execution requires its exact newly activated sole dispatcher, and holds the existing budget and runner locks. An append-only operational journal consumes the permit before reserving and sending **one fixed Gemini 3.5 Flash-Lite availability request**, with a 25-second deadline and 128-output-token maximum. Its conservative reservation is $0.0010841. It contains no financial question or document, and has no retry.

Only HTTP success, exact expected output, valid reported usage within the reservation, matching frozen source and a drained single-request dispatcher can produce verified success. Durable verification is written before the new probe record becomes known-cost. Failed, malformed, interrupted or over-bound probes retain an unknown-cost record and at least their conservative charge, leaving the unchanged runtime circuit blocked. Original records, reservations and policies are never replaced. The tool never restarts the study or retries an episode.

The private launch guard moves ownership, replay, pacing and absolute-deadline checks into the local command that supplies curl configuration. An expired request receives the existing timeout footer and **no network URL**. This reduces the stale-deadline window; it does not make a chat-hosted dispatcher durable or guarantee that the operating system cannot pause later. Request deadlines are not enlarged. Its 22 synthetic tests and harmless local file-only invocation passed, with independent review. No default curl configuration was present in the observed environment. Private queue files and credentials remain excluded from publication.

## First recovery attempt: launcher compatibility defect

The operational change was published in commit `940226cce4520a46a741f013a45538f64efea188`; [full CI](https://github.com/rayidali/spiich_homework/actions/runs/41167973076) passed application verification, Compose and native research checks. Before permit preparation, 1,201 completed historical queue sets were moved into a private archive with exact bytes, modes and timestamps preserved. Their old completion format was retained, not rewritten to claim modern completion evidence. The [sanitized archive receipt](../evidence/research-legacy-queue-archive.json) records the verification.

The first permit was prepared against 3,119 existing usage records. Execution consumed it and reserved $0.0010841. The launcher then rejected the actual queued configuration with `INVALID_DIRECTIVE_VALUE`: the frozen request generator encodes an actual final newline in `write-out`, while the new guard's synthetic fixture had used a literal backslash followed by `n`. The guard therefore rejected a valid completion directive before emitting a network configuration. Curl exited 2 locally; no launch receipt, response, headers or completion footer was created. The recovery command later failed with `RESEARCH_TRANSPORT_RECOVERY_DISPATCHER_NOT_DRAINED`.

This is a launcher integration defect missed by the synthetic tests, not evidence of provider unavailability. The [rejection receipt](../evidence/research-transport-recovery-local-rejection-01.json) binds the archived request, stopped controller, unchanged 3,120-record ledger and consumed/reserved journal. Independent read-only review confirmed the original 3,119-record prefix, policies, frozen source and all 777 outcomes are unchanged. The three request files and two locks belonging to the exited recovery process were archived before stale-lock cleanup; their contents were not rewritten.

At that checkpoint, the circuit stayed blocked. Repair had to test the real frozen request generator and could not turn this failed attempt into success or reuse its expired request. A separately journaled continuation could complete the originally authorized single provider probe only when the archived configuration and old launcher's control flow independently proved rejection before configuration emission. An ambiguous or actually dispatched attempt could not qualify. The original consumed permit and unknown reservation remained intact, with the continuation consuming its own one-use authorization and additional reservation under the existing caps.

The [corrected launcher evidence](../evidence/research-launch-guard-v2.json) records 25 passing tests, including the actual frozen queue writer, and an independent real-curl parsing check against a local file with no network. The [separate continuation helper](../../scripts/continue-unlaunched-probe.ts) binds this exact archived rejection, the old launcher, its actual generated configuration, the stopped controller, both original journal events and all 3,120 existing usage records. The old recovery tool and its consumed guard remain unchanged. The continuation has its own append-only journal and can reserve only one additional fixed availability request. Failed, ambiguous or over-budget outcomes remain blocked; it cannot continue itself again.

The continuation's 31 tests plus 35 original transport-recovery and 28 quota-recovery tests pass together (94 total), with strict TypeScript and formatting. Independent review reran the 31 + 35 tests in both the workspace and a clean public-source checkout without private tooling; all 66 passed in each. Read-only review also matched the actual archived proof and original bindings. These checks use synthetic credentials and the actual frozen queue writer without provider calls. The no-network conclusion relies on preserved operator evidence and reviewed control flow, not tamper-proof remote attestation. The [engineering receipt](../evidence/research-prelaunch-continuation-local.json) records these distinctions.

## Second recovery attempt: shell transport cannot resolve the host

Continuation revision `ff2bdc784e95fb30b0d775f03550049c7f69eaff` passed [full CI 41169740036](https://github.com/rayidali/spiich_homework/actions/runs/41169740036) before execution. The corrected guard emitted configuration with 24,742 ms remaining, but curl returned the complete footer `000 0.000041 6 DAYBOOK_HTTP_DONE_V1`: DNS resolution failed, and no HTTP response was received. The [failure receipt](../evidence/research-prelaunch-continuation-result.json) retains the additional $0.0010841 reservation. This was an attempted network dispatch and does **not** qualify for the pre-launch exception.

The dispatcher stopped cleanly. Independent review confirmed that all 3,120 prior records, both original policies and journals, source/protocol/index/reviewer settings and the bytes of all 777 episodes remained unchanged; the ledger then contained 3,121 records. The original availability and pre-launch continuation tools remain consumed. Additional funded tracked costs at that stop were $2.7619927 for Gemini and $0.01617588 for Jev, including both failed probe reservations. They are estimates, not invoices.

An unauthenticated diagnostic then sent the same public-host configuration through two command forms. Ordinary `curl --config` received HTTP 404; shell process substitution failed DNS with exit code 6. No key, model generation or paid provider operation was involved. The working dispatch form is therefore a private static configuration passed to the already-supported plain curl command. Local validation can prepare that file immediately before the tool call, but it cannot guarantee actual network-launch timing: the original tool-orchestration deadline gap remains a disclosed limitation.

Rather than add another incident-specific exception, the external [operator-admission registry](../../scripts/operator-recovery.ts) permits at most **three additional fixed availability probes and $0.005 in cumulative reservations**, all within the unchanged parent spending caps. Each attempt needs a fresh short-lived operator admission tied to exact history, the repaired dispatcher and concrete evidence; there is no automatic retry, cohort renewal or generic circuit reset. A verified success closes the cohort. Failed attempts and all prior reservations remain intact. The user's standing continuation instruction authorized this bounded maintenance; no fresh user reply, purchase or larger budget was inferred. At that engineering checkpoint no cohort admission or further provider request had occurred; the subsequent result is recorded below.

The registry shares existing operational mechanics through a named export added to the original external tool. Its old consumed refusal and behavior remain intact; exact earlier source bytes were archived before the export-only change. Approved dispatcher paths are fixed, while each fresh admission binds their currently reviewed versions. A repair can therefore be reviewed between completed failed attempts within the same capped registry; helper changes after admission or during a request are rejected. Source, protocol, policies, the initial 3,121 records, both old journals, the prior failure receipt and the bytes of all 777 recorded episodes remain bound.
