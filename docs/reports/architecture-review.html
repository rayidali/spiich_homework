System design · planning snapshotLogical modules—not deployed microservices

Keep authority where it can be enforced.

AI proposes an interpretation. The user confirms it. Server code and PostgreSQL enforce the posting rules. Manual entry skips the model and uses the same review and posting checks.

Protect the money

Balance is required at posting, in base currency. Posted records stay unchanged; corrections use reversals. Drafts can still be incomplete.

Protect the meaning

Balanced does not mean correct. An invoice payment may reduce money owed, rather than create revenue again. Missing facts require clarification.

Protect the operation

Retries must not double-post. A stale review must be rejected. Job retries are safe through stored identities and uniqueness—not exactly-once delivery.

The application has organization-scoped records today. Production authorization would additionally require authenticated users and enforced organization membership.

Lesson from Midday

Its chat retrieves relevant tool descriptions with embeddings. Current receipt matching uses names, dates, amounts and feedback. Retrieval is designed for a specific selection problem.

Lesson from Actual

A confirmed rule such as “this payee → this category” can be understandable and repeatable. Our proposed rule editor would be new work; current Daybook already retrieves confirmed corrections.

Gemini, Jev, pgvector, Mastra, Wren and managed document search have not been integrated. Paid options are acceptable when justified; no purchase or provider spend has occurred during this research.
