## Immediate design decisions

- Error references are tracking numbers, not saved copies of private conversations. Start with safe structured runtime logs. Add Sentry or another service only if the evidence shows the existing runtime-log workflow is inadequate; the user offered access if needed.
- A reviewed posting is the learning boundary. Saving a draft alone does not teach the model. The server stores its own structured proposal and validates the entry binding; arbitrary client-supplied examples are not trusted.
- Posting and recording a meaningful correction are one database transaction. The interface must not claim that a choice was remembered after a separate hidden failure.
- Automatically resolved anomaly alerts retain their history and reason. They are not silently deleted or labeled as user-dismissed.
- Keep numerical accounting in exact deterministic code. Models propose accounts/meaning and ask questions; they do not bypass posting validation or user review.
